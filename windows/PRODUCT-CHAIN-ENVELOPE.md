# Product private-chain envelope v29

This is an engineering protocol for the existing local Ethereum native-to-USDC and Solana private swap implementations. It does not enable production capabilities or qualify any mainnet case. Provider finalizers for the other required private operations and the full 24-case product qualification remain unfinished.

A v29 request retains the exact original v28 proof request, wallet/circuit authorization and genuine proof result, together with the exact v18/v21 unsigned chain request. Its independent domain fingerprint covers every retained field. Device, request, chain, creation time and expiry must match the inner transaction; the inner expiry cannot exceed the original product approval. Both the original authorization/proof and the exact proof bytes embedded in the transaction are reverified before offline approval/signing and before online consumption. Full public wallet identity must match, including its creation metadata.

The offline worker independently reconstructs owned private inputs using the unlocked local wallet. It first signs the v29 envelope approval, then delegates the exact inner request to the existing owner/proof/chain validator and signer. The inner approval also precedes creation of transferable chain bytes. The timestamp records the validated start of that final signature operation. Once bytes exist, final verification uses historical mode so advancing the offchain clock cannot discard the response. This does not authorize new signing after expiry or revoke a previously signed onchain transaction.

The response stores one copy of the raw transaction, its exact hash, and distinct outer and inner wallet approval signatures. Every response verifier checks the complete envelope and original proof, both approval domains, timestamp, transaction bytes/hash and selected wallet. The original response is encrypted before any export picker or renderer reply. Restart/re-export verifies and returns those same bytes; it never signs a replacement or broadcasts automatically. Missing submission history remains uncertain and requires reconciliation of the original hash.

New proof admission writes v29 requests and retains the original immutable v28 journal binding. Older plain v18/v21 proof-bound journals remain readable for recovery, but cannot grant a new detached offline approval. They are never silently migrated or replaced. Historical proof/transaction versions and fingerprint domains remain unchanged. The envelope itself permits cryptographic recovery if a separate admission-journal projection is missing; existing protected records and mismatched/missing-key fail-closed rules remain in force.

The request is limited to 64 KiB, with strict JSON duplicate-key rejection at file handoffs. Signed responses avoid duplicating raw chain bytes and fit the existing 128 KiB plaintext journal limit for the supported finite profiles. The isolated signing worker loads network denial before cryptographic dependencies. Fetch, TCP, TLS/HTTP, HTTP2, UDP, DNS and WebSocket transports are denied. Networking, provider preflight and explicit one-time broadcast stay in the separate online worker. Read-only reconciliation remains available after application expiry.

Local tests use newly generated unfunded wallets, synthetic owned notes/trees, genuine pinned Groth16 proving artifacts and explicit adapter/dialog fixtures. They do not establish native approval/file handoff, physical device separation, provider preparation or mainnet settlement. The production policy still rejects new proof admission, private signing, preflight and broadcast. Safe unsigned cancellation/requote, native view/job preparation, required provider finalizers, merchant consumers and installed-release qualification remain separate work.
