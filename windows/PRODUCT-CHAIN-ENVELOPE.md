# Product private-chain envelope v29

This engineering protocol covers local Ethereum/Solana private swaps and authenticated provider Ethereum deposit/transfer/withdrawal and Solana transfer/withdrawal proofs. It does not enable production capabilities or qualify any mainnet case. Fresh positive qualification, separate Solana deposit planning and the full 24-case product remain unfinished.

A v29 request retains the exact original v28 proof request, wallet/circuit authorization and genuine proof result, together with the exact v10/v16/v18/v21 unsigned chain request. Its independent domain fingerprint covers every retained field. Device, request, chain, creation time and expiry must match the inner transaction; the inner expiry cannot exceed the original product approval. Both the original authorization/proof and the exact proof bytes embedded in the transaction are reverified before offline approval/signing and before online consumption. Full public wallet identity must match, including its creation metadata. Provider results additionally retain and verify the provider's original signed envelope; a legacy proof cannot substitute for that authority. Canonical Solana wire decoding reconstructs the full proof, encrypted outputs, root index and zero-fee/signer parameters before exact comparison.

The offline worker independently reconstructs owned private inputs using the unlocked local wallet. It first signs the v29 envelope approval, then delegates the exact inner request to the owner/proof/chain validator and signer. Direct Ethereum signing also reconstructs its calldata/signed-message hash and wallet-owned H0/H1/stealth identity, then verifies genuine Groth16 before any transaction signature. Direct Solana spending verifies Groth16 in addition to independent owned-note, public-signal and circuit-authorization checks. Invalid proof byte values are rejected before buffer conversion. The inner approval also precedes creation of transferable chain bytes. The timestamp records the validated start of that final signature operation. Once bytes exist, final verification uses historical mode so advancing the offchain clock cannot discard the response. This does not authorize new signing after expiry or revoke a previously signed onchain transaction.

Online direct Ethereum preflight pins the provider profile's registered wrapper, wrapper runtime, verifier getter and Groth16 runtime/key identity at one fixed block. It repeats registration and canonical-header reads. The four provider profiles come from independent deployment/key cross-checks; a changed or unsupported verifier fails closed. Broadcast repeats exact preflight and current expiry checks before its single explicit submission. Solana preparation caps the chain lifetime at the original product deadline and computes exact account rent; preflight invalidates an approval when that rent changes.

The response stores one copy of the raw transaction, its exact hash, and distinct outer and inner wallet approval signatures. Every response verifier checks the complete envelope and original proof, both approval domains, timestamp, transaction bytes/hash and selected wallet. The original response is encrypted before any export picker or renderer reply. Restart/re-export verifies and returns those same bytes; it never signs a replacement or broadcasts automatically. Missing submission history remains uncertain and requires reconciliation of the original hash.

New proof admission writes v29 requests and retains the original immutable v28 journal binding. Older plain v18/v21 proof-bound journals remain readable for recovery, but cannot grant a new detached offline approval. They are never silently migrated or replaced. Historical proof/transaction versions and fingerprint domains remain unchanged. The envelope itself permits cryptographic recovery if a separate admission-journal projection is missing; existing protected records and mismatched/missing-key fail-closed rules remain in force.

The request is limited to 64 KiB, with strict JSON duplicate-key rejection at file handoffs. Signed responses avoid duplicating raw chain bytes and fit the existing 128 KiB plaintext journal limit for the supported finite profiles. The isolated signing worker loads network denial before cryptographic dependencies. Fetch, TCP, TLS/HTTP, HTTP2, UDP, DNS and WebSocket transports are denied. Networking, provider preflight and explicit one-time broadcast stay in the separate online worker. Read-only reconciliation remains available after application expiry.

Local tests distinguish fresh unfunded cryptography, historical public proof recovery, synthetic owned notes/trees and explicit public-state/adapter/dialog fixtures. Historical fixture clocks never authorize new signatures or provider calls. These tests do not establish native approval/file handoff, physical device separation or mainnet settlement. The production policy still rejects new proof admission, private signing, preflight and broadcast. Fresh Solana provider finalization, complete native planning/note/recipient/settlement flows, merchant consumers and installed-release qualification remain separate work.
