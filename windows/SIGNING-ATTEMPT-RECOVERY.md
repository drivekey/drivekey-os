# Interrupted signing and exact-response recovery

Signing uncertainty belongs to the selected wallet in this Windows profile. The existing Electron profile lock enforces one writer; a process-wide wallet guard also prevents competing coordinator instances. An unresolved attempt blocks new transaction and private-proof signatures for that wallet, and blocks local submission before native broadcast confirmation or an online worker. Read-only reconciliation and recovery of already verified original bytes remain available. This is not a cross-device or cross-profile consensus mechanism.

After normal backup verification, review and native approval, the app verifies the vault passphrase without creating transaction authority. It then writes and rereads an exclusive encrypted attempt claim before starting a signing child. A wrong passphrase or a canceled native approval creates no claim. Once the claim exists, a timeout, exception, cancellation, window closure or process death is conservatively unknown until the original response is recovered. There is no reset, delete, replacement or retry endpoint. The claim is immutable and retains the original public request and authority domain.

A completed child response is snapshotted and encrypted in the signing-results journal before another worker, UI-scope check or primary signature-journal write. Independent response verification precedes export. The app also attempts the primary signature/authorization journal. If either contains the exact original response, restart recovery can verify and export those same bytes without signing again. Conflicting results, malformed or partial records, missing attempts for fallback results and missing/mismatched journal keys fail closed and preserve records.

Signature publication preserves encrypted temporary files when writing, fsync, exclusive publication or verification fails. Reads and history include valid interrupted publications; duplicate ciphertext copies must decrypt to the same complete record. Damaged or conflicting fragments are retained and rejected. A successfully verified final publication may remove its redundant temporary link. Original legacy records and cryptographic domains remain unchanged.

Both signing-attempts-v1 and signing-results-v1 participate in protected-key preservation, including interrupted .tmp files and Windows case variants. Before signing, bounded input and worst-case response capacity must fit the existing 128 KiB plaintext journal format. Private-proof requests retain their existing 96 KiB limit; chain requests retain the 64 KiB signer limit. No plaintext fallback, secret logging, implicit network operation or new budget exception is introduced.

Transaction and private-proof histories show signing uncertainty without an export or new-approval action. An original response that remains unavailable can leave the wallet blocked in this profile; uncertainty is not converted into permission merely because time passed or no local response was imported. A separately exported offline request may already have been signed elsewhere; safe cancellation/requote across that handoff remains separate unfinished work.

Local tests use explicit worker/dialog failures, encrypted disposable files and synthetic unfunded cryptography. They do not establish successful native approval/file handoffs, physical device separation, mainnet settlement or release qualification. Production private capabilities remain closed pending their required qualification.
