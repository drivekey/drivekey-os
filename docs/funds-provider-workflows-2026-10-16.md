## Recovery improvement implemented

The official status schema explicitly allows `feeAmount` and `networkFee` to be null. Previously a non-refund status with either null fee threw before returning independently checked status of the already-signed deposit. Recovery now returns `provider-terms-unavailable` and the original provider status. Failed, expired and completed provider states are not relabelled pending or accepted as settlement.

This branch still requires the correlated exact order, provider, fixed-rate flag, network/token identities, deposit/payout/refund addresses, exact amounts, all three saved deadlines, empty memo fields and any supplied deposit hash to match. A nonnull remaining fee must match the saved signed approval. Missing fields and changed terms still fail. The result contains only deposit observation and an unavailable-terms warning, with `providerTermsVerified:false`, `exchangeSettlementVerified:false` and `canResubmit:false`. It never checks or claims a payout, substitutes zero fees, rewrites approval, extends deadlines or authorizes a retry. Strict preparation and signing still reject null fees. The existing separate refund-unverified behavior is retained.

Root performed a static internal review and requested additional substitution negatives, which pass. This is not an independent audit. Focused tests cover null fees across all seven non-refund statuses, either/both null fields, strict fixed-term rejection, recipient/refund/amount/network/token/deadline/hash substitution, surviving-fee changes and refund separation. The final six-suite run passed 167 tests; one existing PostgreSQL integration test was skipped because this run did not launch its private database. Previously recorded PostgreSQL acceptance is separate. Full TypeScript passed before the final additional parameterized test cases. The wider provider inspection run passed 173 tests.
